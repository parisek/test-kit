# src/design

A side of supplied or rendered design images, and the pair that compares it with a captured run. Spec R4.6, R5.5, R8.15.

`import.js` implements `import --side <id>`. `importDesign` reads the images that `target.design` maps under the `root` of a design side and writes an immutable run in the layout of a capture. The providers `files` and `figma` open no browser. The provider `files` opens no network connection. The provider `figma` does, only during `import` (R5.5). The provider `claude-design` opens Chromium on a loopback server. The browser reaches only that server: other HTTP requests are aborted, WebSockets close, and an init script removes WebRTC and WebTransport, and a proxy that closes every connection guards the browser. A worker keeps WebTransport, and the route does not see a worker WebSocket, a shared worker or a prefetch. There the proxy is the guard. The server answers only under a random path token. `readDesignFile` resolves one path against the real root, refuses an escape (a `..`, an absolute path, a symlink that leaves the root), and reads a regular PNG file of at most 40 MiB. Every check runs before a run directory exists, so a failed import leaves no run.

`paths.js` is pure. `designPathProblem` and `designRootProblem` give the reason a configured path is refused, or null. The configuration check (`src/config/normalize.js`) and the import use them.

`png.js` is pure. `readPngSize` reads the size from the header. `expectedWidth` and `widthProblem` give the width rule of R8.15 and the diagnostic that names both sizes. `designProvenance` builds the record of one image: `{ provider, source, importedAt, sha256, width, height }`.

`compare.js` is pure. `isDesignRun` reads the stored side kind. `designPairProblem` gives the reason a cell of a pair with a design run is `incompatible`, or null. `src/compare/runs.js` calls it. It skips the browser settings, tool and scope checks for such a pair.

A viewport with no mapped file has no capture entry, so a pair reads it as `missing` (R8.7), never `match`. A design image never gets cropped or resized.

`figma-ids.js` is pure. It checks the file key, the node ID, the token form and the image URL (https, no credentials, no port, a Figma image host), and gives the export scale of a viewport.

`figma.js` is the only file here that uses the network. `readToken` reads `FIGMA_TOKEN` from the environment and fails before any request. `downloadFigmaImages` asks the Figma API for the images (one call for each batch of node IDs and each scale), then downloads each returned URL. The token goes to the API only. It follows no redirect, retries nothing, bounds time and bytes, and puts no URL or token in an error. One deadline (10 min) covers the whole import: each request gets the smaller of its own timeout and the time left. The host list accepts any S3 bucket named `figma-*`; the owner pins exact bucket names after the live check. `apiBase`, `fetchImpl`, `imageUrlProblem`, the timeouts, the deadline and the total cap are hooks for tests: no option or key sets them.

`claude-design-refs.js` is pure. `parseArtboardRef` splits an artboard reference (`Example.dc.html` or `Example.dc.html#<selector>`) at the first `#` and checks the path. `servedPathProblem` decodes a request path of the loopback server and refuses `..`, hidden names, escaped `/` and control characters. `captureClip` gives the screenshot band: x = 0, the viewport wide. `RENDER_STATE` is the readiness test as text, so the file holds no DOM code.

`claude-design.js` is the render part. `prepareCanvas` checks `root/project/`, reads the runtime `project/support.js`, each mapped artboard and then every other file under `project/` once through `readProjectFile` (real path inside `project/`, regular file, 40 MiB), and keeps the bytes in memory. After the real-path check, `readProjectFile` requires that a `stat` of that path and the opened handle agree in device and inode, and that the real path is the same after the open. On POSIX the open also refuses a symbolic link in the last name. The snapshot skips hidden names and does not follow a symbolic link to a directory. It leaves out a link that leaves `project/` and a file that is not a regular file. More than 2000 files or 256 MiB together fail the import (`PROJECT_LIMITS`, a hook for tests). `projectSha256` hashes the sorted list of `<path>\0<sha256>\n`. `startCanvasServer` serves `project/` on `127.0.0.1` (GET and HEAD, `Host` must name the server, the first path segment must be the random token of the server, `tokenMatches`) from that snapshot only, so a file changed after the check never renders. `renderCanvas` launches Chromium with host names that never resolve, sends every connection that is not for the server through a proxy that closes it (`chromiumArgs`, `startDeadProxy`), adds `NO_SOCKETS_SCRIPT` to each context so no frame has WebRTC or WebTransport, routes every HTTP request that is not for the server under its token to an abort, waits for the render, stops motion and takes each band. An artboard that navigates the top page fails the cell with "Artboard navigated away" and the cell name: a random mark on the loaded document tells it from a new one. One deadline of `screenshot.timeoutMs` covers each cell, from the new page to the screenshot; at the deadline a timer closes the page and fails the cell, because `page.evaluate` takes no timeout. The runtime never comes from the package: the server only serves the copy in the export. `chromium` is a test hook.

With the config key `artifacts` holding `layout`, a `claude-design` import also reads the layout records of each target with `layout.parts`, in the rendered artboard, after the screenshot. It uses the selectors of the imported side (`selectorBySide`). The run then stores `settings.artifacts` `["screenshot", "layout"]`, the layout files and a `test-kit-layout` tool. `designLayoutSettings` gives the layout hash: extractor, bounds, provider and viewports. An invalid part selector or a record over 2 MiB fails the import (#350 part C).

Not built: a `design` key that a target generator reads from a component definition (`import` refuses `targetSource`). It stays open on issue #288.
